🤖 AI DEVELOPMENT CENTER

AI-Assisted ≠ AI-Built

Modern development increasingly involves AI-assisted coding. The goal of this project is not to avoid AI. The goal is to learn how to use AI while maintaining engineering judgment, testing, security awareness and ownership of the final product.

Project standard: AI can accelerate implementation. You remain responsible for requirements, architecture, correctness, testing, security, decisions and final code quality.

🤖 AI SHOULD DO

  • Generate boilerplate code
  • Create initial component implementations
  • Suggest database schemas
  • Generate test cases
  • Explain unfamiliar APIs
  • Find potential bugs
  • Suggest refactors
  • Generate documentation drafts
  • Help debug errors
  • Review pull requests

🧠 YOU SHOULD DO

  • Define the actual problem
  • Decide what features matter
  • Design the architecture
  • Understand generated code
  • Verify calculations
  • Test edge cases
  • Review security implications
  • Choose between competing approaches
  • Debug failures
  • Make the final decision

🔄 AI Development Workflow

Every meaningful feature should follow this loop.

1
YOU — Define the requirement

Write what the feature should do, what inputs it receives, what outputs are expected, and what edge cases matter.

2
AI — Propose an implementation

Ask AI for an implementation, alternatives and potential tradeoffs.

3
YOU — Understand it

Ask AI to explain unfamiliar sections. Do not accept code you cannot explain.

4
YOU + AI — Test it

Run automated tests, manual tests and edge cases.

5
AI — Review it

Ask AI to aggressively look for bugs, security problems, maintainability issues and missing tests.

6
YOU — Accept, reject or modify

Never blindly accept AI recommendations.

7
YOU — Commit a clean change

Keep changes small enough that you can explain them in an interview.

🧠 AI Prompt Library

Use AI as a senior engineer, reviewer and teacher — not as an unquestioned code generator.

Architecture "Before writing code, propose 2–3 architectures for this feature. Compare their tradeoffs, complexity and maintainability."
Explain "Explain this code to me as if I need to defend this implementation in a technical interview. Identify anything I should understand deeply."
Testing "Create a comprehensive test plan for this feature. Include normal cases, edge cases, invalid input, boundary values and failure states."
Security "Review this implementation for authentication, authorization, injection, data exposure, insecure dependencies and other security risks."
Code Review "Review this change as a senior engineer. Do not rewrite everything. Identify correctness, maintainability, performance and security problems."
Challenge Me "Ask me five technical questions about this implementation that an interviewer could ask. Do not give me the answers until I respond."

🛡️ Engineering Quality Standards

These are the standards the project should aim for before you call it portfolio-ready.

🧪 Testing Unit + integration tests for important logic.
🔐 Security Validate input, protect user data, avoid exposed secrets.
🧹 Code Quality Clear naming, modular components, linting and formatting.
📦 Dependencies Know why each major dependency exists.
🌐 Accessibility Keyboard navigation, labels, contrast and semantic HTML.
📱 Responsive Laptop, tablet and mobile layouts.
⚡ Performance Avoid unnecessary requests and expensive work.
🔄 Git Small meaningful commits and useful commit messages.
🚀 Deployment GitHub → Vercel → production environment.
Portfolio standard: You should be able to explain every major architectural decision in the project.
